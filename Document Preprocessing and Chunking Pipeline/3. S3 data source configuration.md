# S3 data source configuration  
We covered local parsing and chunking earlier. On AWS, Knowledge Bases for Amazon Bedrock ***automates*** this: just upload documents to S3 and connect it as a data source.  
Two key concepts: A data source defines where documents are read from (S3 bucket and folder) and how they're *parsed and chunked*; one Knowledge Base can have several. Sync (an ingestion job in the API) parses, chunks, and embeds current documents into the vector index. **Uploads aren't searchable until you sync.**

## S3 bucket setup and data upload  
Set up an S3 bucket for RAG documents. A well-organized folder structure eases later metadata filtering. *S3 has no real folders;* object key prefixes, as in `hr/2025_HR_Guide.pdf`, just look like folders.  
S3 bucket names must be *unique* across all AWS accounts worldwide. If `my-rag-documents` is already taken, add your account ID or similar, e.g., `my-rag-documents-123456789012`. Creating a bucket without a region setting works only in `us-east-1`; elsewhere, specify the location constraint.  

Note: **Metadata JSON files must be named `original-filename.metadata.json`**. For example, `report.pdf` needs `report.pdf.metadata.json` for Knowledge Bases to detect it automatically. Keep it in the same folder as the source.  

## Connecting a knowledge bases data source  
Once the documents are uploaded to S3, connect the bucket as a data source to Knowledge Bases using boto3's bedrock-agent client. There are two APIs: bedrock-agent for managing Knowledge Bases and syncing data, and bedrock-agent-runtime for querying them.  
The vectorIngestionConfiguration below defines chunking settings from Section 9-2. maxTokens sets the maximum tokens per chunk, while overlapPercentage controls the overlap between adjacent chunks.  

\# 3_kb_create_data_source.py
bedrock_agent = boto3.client("bedrock-agent", region_name="us-east-1")  

\# Add an S3 data source to the Knowledge Base  
response = bedrock_agent.create_data_source(  
    knowledgeBaseId="YOUR_KB_ID",  # Existing Knowledge Base ID  
    name="hr-documents",  
    description="HR team document data source",  
    dataSourceConfiguration={  
        "type": "S3",  
        "s3Configuration": {  
            "bucketArn": f"arn:aws:s3:::{bucket_name}",  
            "inclusionPrefixes": ["hr/"]  # Include only the hr/ folder  
        }  
    },  
    vectorIngestionConfiguration={  
        "chunkingConfiguration": {  
            "chunkingStrategy": "FIXED_SIZE",  
            "fixedSizeChunkingConfiguration": {  
                "maxTokens": 512,        # Maximum 512 tokens per chunk  
                "overlapPercentage": 20   # 20% overlap  
            }  
        }  
    }  
)  

data_source_id = response["dataSource"]["dataSourceId"]  
print(f"Data source created: {data_source_id}")  


## Automatic sync setup  
After connecting the data source, run Sync to chunk and embed S3 documents and store them in the vector index. Sync is asynchronous, so *periodically check its status until completion*.  

Run Sync whenever you add or update documents in S3. Only changed documents are processed, and deleted documents are removed from the vector index during the next sync.  

S3 data source sync must be triggered *manually*. Uploading documents does not start it automatically. **To automate this, use S3 Event Notifications with a Lambda function** to call start_ingestion_job whenever a file is uploaded.  


# Sync validation check point
A COMPLETE sync status does *not guarantee that all documents were processed successfully*. Verify the following:  
- Does *the number of scanned documents in statistics match* the number of documents uploaded to S3 (within the configured prefix)?  
- Are *any documents failed to index*? Check failureReasons or the console sync history for issues such as unsupported formats, file size limits, or invalid metadata formats.
- Confirm that the *expected document chunks are retrieved along with their metadata*.
